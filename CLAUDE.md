# CLAUDE.md

E-ink dashboard (weather, calendar, and a power meter view) that runs on a jailbroken Kindle Paperwhite, with no server. The Kindle downloads the data, renders with awk, and draws with FBInk. The Mac is used only to build, preview, test and publish.

## Target device

- Kindle Paperwhite 2, 758×1024, firmware 5.12.2.2, WinterBreak2 jailbreak, BusyBox v1.28.3, 32-bit ARM (`input_event` = 16 bytes).
- The scripts run as root. The Kindle clock is UTC. Local time = UTC + `utc_offset_seconds` from line 2 of `weather.csv`.
- FBInk 1.25.0 is at `/mnt/us/libkh/bin/fbink`. It has image and TrueType support. `fbink -e` crashes (segfault): do not use it.
- Touchscreen: `/dev/input/event1` (`cyttsp4_mt`). Power key: `/dev/input/event0` (`max77696-onkey`).
- KUAL is not installed. The dashboard starts from scriptlets in `/mnt/us/documents` (`kindle/documents/*.sh`).
- `/mnt/us` is FAT. A `mv` from `/tmp` to `/mnt/us` warns about ownership: write temp files next to the target.
- While USB is connected, the Kindle cannot write to `/mnt/us`. Stop the dashboard before USB.
- `/mnt/us` is a FUSE mount (`fsp`) over the FAT at `/mnt/base-us`. In USB drive mode it can be gone: the USB stop runs `stop.sh` from `$TMP`.
- Cable signal: `/sys/devices/system/wario_charger/wario_charger0/connected` (1 = cable). A Mac and a wall charger give the same values in all signals (probe 2026-11-13). `volumd driveModeState` stayed 0 after the eject.
- The Mac shows file times that the Kindle wrote as UTC, and the times that the Mac wrote as local time.

## Layout

- `kindle/kindledash/` = `/mnt/us/kindledash` on the Kindle. Every file here goes to the Kindle (see `MANIFEST`).
  - `loop.sh`: main loop. Wi-Fi on, download, update check, Wi-Fi off, render, draw, suspend to RAM with an RTC alarm.
  - `render.awk`: layout. Writes draw commands `T|font|px|left|right|top|color|flags|text`, `I|file|x|y`, `R|x|y|w|h|color`.
  - `ical.awk`: ICS parser (RRULE, EXDATE, RECURRENCE-ID, VTIMEZONE). Output `day|order|start|end|title`.
  - `common.awk`: date functions for both awk scripts.
  - `tibber.sh`: Tibber Pulse Bridge reading, daily Google Sheet row (`push`), sheet rows for the chart (`days`). Ported from github.com/biki/pizero (Raspberry Pi).
  - `meter.awk`: SML and plaintext OBIS decoder (1.8.0, 16.7.0). No CRC check: `push` reads twice.
  - `tibber.awk`: meter view. `loop.sh` appends it after `render.awk`. Both END blocks run, guarded by `view`.
  - `update.sh`: pulls new versions from GitHub by `MANIFEST` (MD5 per file) and checks them before use.
  - `fontdata.awk`, `fonts/`, `icons/`: generated by `tools/build.py`. Do not edit them by hand.
  - `kindledash.conf`: public settings (in git, shipped with updates).
  - `secrets.conf`: calendar URLs, Tibber bridge address and password, sheet URL and token. Only on the Kindle. Never commit it, never write it to the repo.
- `tools/`: Mac tools (uv project). `icons.py` draws the icons. `preview.py` draws the draw commands with FBInk's font metrics.
- `tools/sheet/Code.gs`: Apps Script web app in the Google Sheet. The Kindle POSTs to it with a token (no service account on the Kindle).

## Commands (from the repo root)

```sh
uv run --project tools python tools/build.py              # fonts, fontdata.awk, icons (after a change to icons.py or fonts)
sh tools/dev-render.sh /tmp/dash.png [file.ics] [de|en]   # real loop.sh once in busybox (Docker), then a PNG preview
uv run --project tools --with icalendar --with recurring-ical-events python tools/test/check_ical.py
sh tools/test/check_update.sh                             # update.sh against a local busybox httpd
sh tools/dev-render.sh /tmp/meter.png "" de tibber          # meter view with a fake bridge
uv run --project tools --with smllib python tools/test/check_meter.py   # meter.awk against smllib
sh tools/test/check_tibber.sh                             # tibber.sh with a fake bridge and a fake Apps Script
sh tools/release.sh "message"                             # MANIFEST, commit, push: the Kindle installs it over Wi-Fi
```

Docker must run for the busybox tests. `BUSYBOX=busybox:1.28.3` runs `dev-render.sh`, `check_meter.py`, `check_tibber.sh` and `check_update.sh` in the Kindle's BusyBox version (default 1.36). Check shell syntax with busybox: `docker run --rm -v "$PWD:/w:ro" busybox:1.36 sh -n /w/<file>`.

## Rules

- Write device code for BusyBox `sh` and BusyBox `awk`, not bash or gawk. Test it in busybox (Docker), not with the macOS tools.
- BusyBox awk: do not write `name (expr)`. BusyBox can parse it as a function call. Use a temp variable. Do not use gawk functions (`gensub`, `strftime`, `asort`).
- BusyBox awk has gawk's `RT` as a special variable (it holds the record terminator). Do not use `RT`, or other gawk special names, as a global. Do not use built-in names (`sub`, `index`, ...) as parameters.
- `update.sh` on the Kindle is the old version when it installs a new one. A new file that `render.awk` needs breaks the old test render: keep `render.awk` complete on its own.
- BusyBox awk reads one `-f` file safely. `loop.sh` joins `fontdata.awk`, `common.awk`, `render.awk` and `tibber.awk` into one file before it runs them.
- Text positions: FBInk `px` = ascent − descent height (`stbtt_ScaleForPixelHeight`). Baseline = `top + ceil(scale × ascent)`. `render.awk` takes baselines and em sizes and converts them. FBInk wraps text that is too wide, so keep every text inside its box (`fit()` cuts it with "…").
- FBInk cannot right-align TrueType text. `render.awk` measures the width with `fontdata.awk` and sets `left`.
- Icons are baked on their background (white 255 or card gray 238). FBInk draws them without transparency here.
- Do not use white text. On this Kindle, FBInk 1.25.0 drew white text (`-C WHITE -O`) on a black box as nothing, although the preview shows it. Use black or gray text on light backgrounds. The "today" pill is a black outline (`corner-14-ring-*`) for this reason.
- `tools/build.py` must give the same bytes for the same input (`recalcTimestamp = False`). Otherwise every rebuild makes the Kindle download unchanged files again.
- Shell loops on the Mac: zsh is the default shell. Do not use `path` as a variable name in zsh (it is tied to `PATH`). Run file loops with `sh -c '...'`.
- The repo is public (github.com/biki/kindle-dashboard). Before a push, check that no calendar URL, email address or IP address is in the files. Commit email for this repo: the GitHub noreply address (set in the local git config).
- Commit and push only when the user asks. `tools/release.sh` commits and pushes.

## Deploying

- Normal path: `sh tools/release.sh "message"`. The Kindle checks the `MANIFEST` every `UPDATE_EVERY` minutes during a refresh, and after each power-button press. `update.sh` keeps the old version if a check fails and logs the reason in `loop.log`.
- USB path (first install, `secrets.conf`, logs): the Kindle mounts at `/Volumes/Kindle`. Copy with `cp -X`, then delete the macOS `._*` files. Never overwrite `secrets.conf`.
- Logs: `/Volumes/Kindle/kindledash/loop.log` (UTC times), `probe.txt` from the "Dashboard: Probe" scriptlet.

## Behavior to keep

- Refresh every full hour, no refreshes from 23:00 to 06:00. No clock on the screen (it would not be live).
- Front light: on (`FL_LEVEL`) after start and after a power-button press, for `IDLE` seconds after the refresh. Off before each suspend. `stop.sh` restores the user's level from `fl.saved`.
- A wake more than 60 s before the RTC alarm counts as a power-button press.
- USB cable (`USB_STOP=1`): no start with a cable in, and a plug-in stops the dashboard (two reads 1 s apart). Only an explicit `1` counts: a missing file must never block a start.
- Double tap (two `BTN_TOUCH` downs within about 2 s) stops the dashboard. The touch watcher runs in the background, so it works during a refresh.
- Language German (`DASH_LANG=de`), place Ingelheim am Rhein, font Nunito.
- Power meter: off while `TIBBER_HOST` is empty (a release must be safe before the secrets exist). Single tap (no second tap within 3 s) switches the view, saved in `view`. Daily row at `PUSH_AT` (23:55), also in the night pause, with no draw and no light. The row date is the planned day, also for a retry after midnight. The baseline (`tibber.base`) moves only after the sheet confirmed the row.
- Sheet contract (from pizero): A date `dd.mm.yyyy`, B meter total kWh, C daily kWh. Row 1 header, newest row at row 2.
